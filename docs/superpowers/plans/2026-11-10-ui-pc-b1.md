# Interface PC « A · Jaquettes » en B1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redessiner toutes les fenêtres de hakchi (WinForms, net48) dans le langage B1, avec une fenêtre principale « bibliothèque en jaquettes », sans toucher au moteur.

**Architecture:**
- **Socle de thème :** un dossier `hakchi_gui/Theme/` avec :
  - la palette et les polices (Jost embarquée) ;
  - un « skin » qui repeint récursivement les contrôles standard ;
  - un rendu ToolStrip ;
  - une barre de titre sombre.
- **Fenêtres :** toutes les fenêtres héritent de `B1Form`, qui applique le skin au chargement.
- **Fenêtre principale :**
  - Elle est réorganisée autour de contrôles dessinés sur mesure.
  - La grille de jaquettes est une **vue** posée sur le `listViewGames` existant, qui reste en place, caché, comme source de vérité. Les sélections et les cases cochées passent par lui, si bien que les 111 usages du code moteur et des autres fenêtres continuent de marcher sans changement.
  - Les 148 entrées de menu existantes sont **re-parentées** dans les menus de la barre du haut, jamais recréées.

**Tech Stack:**
- C# / .NET Framework 4.8 / WinForms (GDI+).
- xUnit 2 sur un nouveau projet de tests net48, hors solution.
- Jost (OFL, déjà dans `theme/fonts`).

**Spec:** `docs/superpowers/specs/2026-11-10-hakchi-snes-usa-refonte-design.md` (§6 projet 3, §7 optimisation, §8, §8 bis).
**Maquette validée :** `.superpowers/brainstorm/9314-1794315727/content/hakchi-pc.html` (option A).

## Global Constraints

- **Ce qui ne bouge pas :**
  - .NET Framework 4.8 / WinForms, sans migration de framework.
  - Le moteur n'est pas réécrit : flash, FEL, synchronisation, mods, installation et désinstallation de hakchi.
  - Les écrans de flash et d'installation gardent **exactement** le même comportement et les mêmes confirmations. Seule leur apparence change.
  - Aucune fonction n'est supprimée. On peut réorganiser l'accès (flash, mods, sauvegardes, Game Genie, réglages, dumper, etc.), pas retirer.
- **Palette B1** (maquette) :
  - fonds : `#1C1B22` fond, `#26252E` ligne active, `#2C2A34` filet ;
  - accents : `#4A3C8C` bouton primaire, `#6B5BB5` accent et barre, `#A79FD6` lavande, `#5C5870` pointillé ;
  - textes : `#E4E2EA` texte, `#ECE9F8` texte sur bouton, `#B6B2C4` texte secondaire, `#8E8A9C` texte atténué, `#6F6B7E` texte discret ;
  - hachures `#24232B` / `#2A2932` ;
  - état : `#7BC47F` console en ligne (pastille seulement), `#D9776A` erreur.
  - Aucune autre couleur.
- **Pas d'« AI slop » :** aucun dégradé décoratif, halo, ombre portée, glassmorphism ou néon. Coins droits ou 2 px au plus. Filets de 1 px.
- **Typographie :**
  - Jost : Medium pour le texte, SemiBold pour les titres, Regular pour les petites étiquettes.
  - Repli : « Segoe UI » si la police embarquée ne se charge pas.
  - Les titres de section sont en capitales avec un espacement de 0,14 em.
- **Textes :**
  - Les nouveaux textes passent par resx, en FR et en EN. Les 7 autres langues retombent sur l'anglais.
  - Les textes existants et leurs traductions sont conservés.
- **Perf (§7), mesurée avant et après avec la méthode de `docs/superpowers/notes/baseline-perf.md` :**
  - démarrage B, fenêtre principale visible : pas plus de +5 % ;
  - premiers jeux affichés (C) : pas plus lent ;
  - grille de ~257 jaquettes : premier rendu complet en moins de 1 s sur la copie de test.
- **Machine et disques :**
  - J: est presque plein. Les builds et sorties lourdes vont sur `P:\HakchiSNESUSA\`.
  - Le build se lance avec le script de build de la session (`N:\tools\env.cmd` puis `msbuild hakchi_gui.sln /p:Configuration=Debug "/p:Platform=Any CPU"`).
  - La copie de test est `P:\HakchiSNESUSA\app\hakchi_new.exe`, patchée pour le mutex, à redéployer avec `robocopy ... /E /R:2 /W:1`.
- **Interdits :**
  - Ne jamais utiliser les boutons Synchroniser ou Exporter, ni rien qui écrive sur la console, depuis une session de test.
  - Ne jamais modifier `R:`.
  - Ne jamais tuer un processus par nom d'image : toujours par PID.
  - La clé TheGamesDB n'est jamais affichée, journalisée ni commitée.
- **Git :** commits sur la branche `snes-usa/ui-pc`, créée depuis `snes-usa/theme-b1`. Push seulement vers `origin`, et sur demande.

## Review Focus

- **Fenêtres en 125 / 150 % de DPI :**
  - Rien n'est tronqué ni ne se chevauche.
  - Les contrôles dessinés sur mesure se mettent à l'échelle avec `DeviceDpi`.
  - Testé dans la Task 2 (rendu à 96 et 144 dpi) et dans la Task 5.
- **Grille avec un filtre actif, puis Synchroniser, Exporter ou le gestionnaire de dossiers :** l'opération porte sur **tous** les jeux cochés, pas seulement les visibles. C'est garanti par l'architecture « vue sur listViewGames » et testé dans la Task 3.
- **Langue arabe (RTL) et langues aux libellés longs (de-DE) :**
  - Les mises en page redessinées ne cassent pas.
  - Les surcharges de mise en page des resx localisés sont retirées.
  - Testé dans la Task 10.
- **Jeu sans jaquette, jaquette corrompue ou très grande :** la grille affiche les hachures « sans jaquette » sans exception et sans geler l'interface (décodage en tâche de fond). Testé dans la Task 3.
- **Police Jost absente ou bloquée** (PrivateFontCollection en échec) : repli sur Segoe UI, sans exception. Testé dans la Task 1.

    - `string System` (null = tous) ;

    - `enum Scope { OnConsole, Library }` ;
    - `bool SortAz` ;

  - `ThumbnailCache(int capacity = 512)` :
    - `Image Get(NesApplication app, Size size, Action<NesApplication> onReady)` renvoie l'image en cache, ou `null` et décode en tâche de fond, puis rappelle `onReady` sur le thread UI ;
    - une jaquette illisible donne une entrée « absente », sans exception ;
    - éviction LRU.
  - Rendu d'un jeu sans jaquette : hachures 135° `HatchA`/`HatchB` de 6 px, contour pointillé `Dashed` et « sans jaquette » en `Lavender` (texte resx).
  - Jeu sélectionné : contour `Lavender` de 2 px décalé de 3 px.
  - Jeu coché « sur la console » : petit interrupteur violet strié dans l'angle bas-droit de la jaquette (motif B1).
  - L'item 0 de la source, la ligne « jeux d'origine », est géré à l'identique de l'existant.
